Claude Code

⌨️ Claude Code

Claude with hands — an agent that lives in your terminal/IDE and acts on your machine. Crash-course revision notes.

1 · What Claude Code is

Claude (claude.ai / desktop) is a brain — it can only talk. Claude Code is the same brain with hands: it reads, writes & edits files, runs terminal commands, and calls tools — all on your machine. That's why it must be installed and why it asks for permission before acting. Everything runs on the agentic loop.

2 · Setup & cost

Install & check

Install via the official command (macOS/Linux terminal, Windows PowerShell/cmd)
claude doctor — diagnoses install / node / PATH issues
Windows: add to PATH if claude is "not recognized"
Run in terminal, VS Code / Cursor / JetBrains extension, or desktop app

Paying for it (not free)

Subscription (Pro/Max) — daily/weekly limits · like a gym membership
API key (Anthropic console) — pay per token · like paying per visit
3rd-party — Bedrock / Vertex / local (weaker = not worth it)
Token ≈ ¾ of a word. You pay on input + output tokens; output is pricier.
Model tiers — pick the right one, not always the most powerful
HaikuFastest, cheapest — simple tasks, maintenance, quick lookups
SonnetBalanced — everyday building & most work (good default)
OpusMost powerful — planning, architecture, hard problems (uses limit fast)
Typical flow: Opus to plan → Sonnet to build → Haiku to maintain/debug. Switch with /model.

Slash commands are keyboard-shortcut-style controls that don't burn conversation context.

Session / context

/context — what's filling the window
/cost · /usage — spend so far
/compact — summarize & free space
/clear — fresh session
/rewind — undo code + chat to a checkpoint
/resume — reopen a past session · fork to branch

Config

/model · /effort — brain & thinking depth
/init — generate a CLAUDE.md for an existing repo
/agents · /mcp — manage sub-agents / MCP servers
/login · /logout · fast mode
!cmd — run a raw shell command
btw ... — ask without polluting history

Permission modes (shift+tab)

Plan — read-only, proposes a plan first
Default — asks before each edit/command
Accept edits — auto-edits (93% use this)
Auto — auto + background safety checks
Bypass (danger) — no prompts · avoid
Sessions are saved automatically (id, history, changes). Don't start fresh every day — /resume keeps the context. Exit cleanly with exit.

4 · CLAUDE.md — the project brain

Every session starts with zero memory. CLAUDE.md is the briefing loaded into context every time — project overview, stack, commands, naming, rules, how to verify. Get it right and Claude feels like a teammate of months.

Belongs

Overview, key commands, naming, folder layout
Hard rules / guardrails, how to verify
Short pointers, not copies

Doesn't belong

Full API docs, code snippets, one-off tasks
Solved-problem instructions, stale info
Anything huge — it loads every session
Relevance > length. 60 relevant lines beat 400 irrelevant ones — LLMs follow ~150–200 instructions well, then quality drops. Primacy/recency bias: put the most important rules at top & bottom. Scopes (strongest wins, closest to project): enterprise → global (~/.claude) → project (.claude) → local. Treat it like tech debt — prune, don't grow.

5 · Context management (context rot)

LLM calls are stateless — every message resends the entire history (+ system prompt, tools, MCP). So context fills up, cost snowballs, and quality rots: it starts ignoring CLAUDE.md, repeats work, makes mistakes it wouldn't have 20 messages ago.

Keep the window lean
Lean CLAUDE.md · move detail into skills / agents / settings (loaded only when needed)
Disable unused MCP servers (each adds ~fixed token overhead)
Extended thinking reasons in a side channel — doesn't pollute main context
Plan before you build · review the V1 so early mistakes don't propagate
Trick: keep a changelog.md Claude updates + reads each session

6 · The .claude directory

The hidden .claude/ folder (project or ~/.claude global) is where everything that makes Claude Code "smart & yours" lives.

settings.jsonPermissions, hooks, env, model — .local.json stays out of git
rules/Split-out coding / testing / security rules (keep CLAUDE.md small)
skills/Reusable playbooks (SKILL.md + scripts)
agents/Sub-agent definitions
hooks/ · commands/Event scripts · custom slash commands

7 · Skills

A skill is a reusable, invocable playbook — a SKILL.md (instructions, no LLM needed to define) plus optional supporting scripts/files. Teach Claude a repeatable workflow once, invoke it forever. Loaded only when needed (Claude reads just the description first).

Invoke: auto (Claude matches the description) or manually via /skill-name
Arguments make them dynamic (input path, model, effort…)
Scripts inside the skill = deterministic, cheaper (no re-writing code each run)
Use skill-creator to build/refine skills; scope = project / personal / plugin

8 · Hooks

Hooks are shell scripts that fire automatically on events in Claude's lifecycle (PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionStart/End…). Configured in settings.json. Zero tokens, no LLM, deterministic — they always run.

Automation

Auto-format after every edit, cleanup, etc.

Logging

Record every bash command / session silently

Guardrails

Block dangerous commands (e.g. rm -rf)
Exit code 2 = hard block — stops the tool even in bypass mode (the "you shall not pass"). Exit 0 = allow. Async hooks run in the background.

9 · MCP — Model Context Protocol

Open standard (by Anthropic) for connecting any AI to external tools & data — Gmail, GitHub, Slack, Tavily, browser (Playwright), and more. It's a toolbox of APIs you don't maintain: give Claude the tools (context) so it can act on the world.

Local serverRuns on your machine (npx/uvx), spawned when needed — you update it
Remote serverHosted on the web, no maintenance (e.g. Tavily) — the future default
MCP eats context (tool defs) — disable what you don't use; Sonnet's tool search loads on demand. MCP vs skill: build fast with MCP → for repeatable/token-sensitive production, wrap the exact API in a skill.

10 · Sub-agents & agent teams

A sub-agent is a mini Claude Code session with its own context window, model, tools & permissions. Delegate a noisy task (explore the codebase, review, write tests) — it works in isolation and returns only a summary, saving your main context & money.

Use sub-agents for: isolated, self-contained work · code exploration / review / tests · cheaper models
Skill vs sub-agent: skill = same context, step-by-step now; sub-agent = fresh isolated session
Agent teams experimental — parallel instances that message each other & share a task list; use git worktrees to avoid clashes. Powerful (built a C compiler) but expensive; not on by default.

11 · Plugins & marketplaces

A plugin bundles skills + hooks + agents + MCP + commands into one shareable directory (with a .claude-plugin/plugin.json manifest). Install from marketplaces or share across a team/org so everyone codes with the same setup, tokens & conventions.

Best move for a team: keep a shared plugin/.claude repo — instant onboarding + uniformity. Only vet third-party plugins (they can run scripts / hit APIs). Related: LSP plugins give Claude real code intelligence (go-to-def, references, type errors) instead of treating code as plain text.

12 · Scheduling & automation

Unlike a dumb cron job, a scheduled Claude reasons — it reads errors, tries alternatives, and reports a diagnosis. Three ways:

/loopRepeat a prompt/skill on an interval — but only while the session is open
headlessclaude -p "..." — runs without the UI; pair with cron for real automation on a server
Claude routinesCloud (claude.ai /code) — runs on a schedule/API/GitHub event, laptop off
Safety when it runs unwatched
Start read-only · write output to a non-destructive path
Human gates for irreversible actions (write a summary + ask, don't auto-deploy)
Log everything · test before scheduling · env var can disable all schedules
