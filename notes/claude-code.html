Claude Code

⌨️ Claude Code

Claude with hands — an agent that lives in your terminal/IDE and acts on your machine. Crash-course revision notes.

1 · What Claude Code is

Claude (claude.ai / desktop) is a brain — it can only talk. Claude Code is the same brain with hands: it reads, writes & edits files, runs terminal commands, and calls tools — all on your machine. That's why it must be installed and why it asks for permission before acting. Everything runs on the agentic loop.

2 · Setup & cost

Install & check

Install via the official command (macOS/Linux terminal, Windows PowerShell/cmd)
claude doctor diagnoses install, node, and PATH issues
Windows: add to PATH if claude command is "not recognized"
Run in terminal, VS Code, Cursor, JetBrains extensions, or desktop app
Requires Node.js 18+ to be installed on your system

Paying for it (not free)

Subscription (Pro/Max) has daily/weekly limits, like a gym membership
API key (Anthropic console) means pay-per-token, like paying per visit
3rd-party options include Bedrock, Vertex, or local models (generally weaker)
Token ≈ ¾ of a word. You pay on input plus output tokens; output costs more.
Model tiers choose the right one for your task
HaikuFastest and cheapest; use for simple tasks, maintenance, quick lookups
SonnetBalanced performance; everyday building and most work (recommended default)
OpusMost powerful; for planning, architecture, hard problems (burns limit faster)
Typical flow: Opus to plan, Sonnet to build, Haiku to maintain/debug. Switch with /model.

3 · Commands, modes & sessions

Slash commands are keyboard-shortcut-style controls that don't consume conversation context and cost no tokens.

Session and context

/context shows what's currently filling your context window
/cost and /usage display your cumulative spend so far
/compact summarizes history and frees up context space
/clear starts a fresh new session
/rewind undoes code and chat back to a checkpoint
/resume reopens a past session or forks to a branch

Configuration

/model and /effort switch the brain model and thinking depth
/init generates a CLAUDE.md briefing for an existing repo
/agents and /mcp manage sub-agents and MCP server connections
/login and /logout control auth; /fast enables faster mode
!cmd runs a raw shell command without context overhead
btw ... lets you ask questions without polluting chat history

Permission modes (shift+tab)

Plan is read-only and proposes a plan before acting
Default asks for confirmation before each edit or command
Accept edits auto-applies changes without asking (93% use this)
Auto auto-applies changes plus background safety checks
Bypass (risky) skips all prompts; avoid unless you trust everything
Sessions are saved automatically with ID, history, and changes. Don't start fresh every day. Use /resume to keep your context and previous work. Exit cleanly with exit command.

4 · CLAUDE.md: the project brain

Every session starts with zero memory. CLAUDE.md is the briefing file loaded into context automatically each time. It contains project overview, tech stack, key commands, naming conventions, hard rules, and how to verify work. A good CLAUDE.md makes Claude feel like a teammate with months of context.

What belongs in it

Project overview and tech stack description
Key terminal commands and naming conventions
Folder layout and critical rules/guardrails
How to verify work (tests, build steps, deployment)
Short pointers and links, not full copies

What doesn't belong

Full API documentation or code snippets
One-off task details or solved-problem instructions
Stale information or anything outdated
Huge files or anything loaded every session unnecessarily
Quality over quantity. 60 relevant lines beat 400 irrelevant ones. LLMs follow about 150–200 instructions well, then quality degrades. Primacy/recency: put most important rules at top and bottom. Scope precedence: enterprise settings override global ~/.claude, which override project .claude, which override local settings. Treat CLAUDE.md like tech debt: prune regularly, don't grow unbounded.

5 · Context management (context rot)

LLM calls are stateless. Every message resends the entire history (system prompt, tools, MCP definitions, files). Context fills up, cost snowballs exponentially, and quality degrades (context rot): Claude starts ignoring CLAUDE.md, repeating work, making mistakes it wouldn't have made 20 messages earlier.

Keep the window lean and efficient
Keep CLAUDE.md minimal; move detailed docs into skills, agents, or settings (loaded on-demand)
Disable unused MCP servers; each one adds fixed token overhead to every message
Use extended thinking separately or in a side channel (doesn't pollute main conversation context)
Plan before you build. Review the first version so early mistakes don't cascade
Pro tip: keep a changelog.md that Claude updates and reviews at session start

6 · The .claude directory

The hidden .claude/ folder (project-level or ~/.claude for global settings) is where everything making Claude Code "smart and yours" lives.

settings.jsonPermissions, hooks, environment variables, default model. Use .local.json to keep secrets out of git.
rules/Split out coding, testing, security rules separately to keep CLAUDE.md lean
skills/Reusable playbooks that pair instructions (SKILL.md) with supporting scripts
agents/Sub-agent definitions, each with custom model, tools, and permissions
hooks/ and commands/Event scripts that fire on git/tool events plus custom slash commands

7 · Skills

A skill is a reusable, invocable playbook consisting of SKILL.md (plain instructions, no LLM training needed) plus optional supporting scripts/files. Teach Claude a repeatable workflow once, and invoke it forever. Skills load only when needed: Claude reads the description first and decides whether to invoke.

Invocation: automatic (Claude matches the description to your task) or manual via /skill-name
Arguments: make skills dynamic (input path, model choice, effort level)
Bundled scripts run deterministically and cheaply; you avoid re-writing code each time
Use the skill-creator tool to build, test, and refine skills. Scope is project, personal, or plugin-level

8 · Hooks

Hooks are shell scripts that fire automatically on lifecycle events in Claude Code (PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionStart/End, etc.). Configured in settings.json. Zero tokens, no LLM, fully deterministic. They always run exactly as written.

Automation

Auto-format code after every edit, cleanup temp files, lint on save

Logging

Silently record every bash command, session start/end, cost tracking

Guardrails

Block dangerous patterns like rm -rf, git push --force, or credential leaks
Exit code 2 (hard block) stops execution even in bypass mode ("you shall not pass"). Exit 0 allows. Exit 1 warns but continues. Async hooks run in the background without blocking.

9 · MCP: Model Context Protocol

Open standard (developed by Anthropic) for connecting any AI to external tools and data: Gmail, GitHub, Slack, Tavily, browser automation (Playwright), and more. It's a toolbox of pre-built APIs you don't have to maintain. Give Claude the tools so it can act on the external world directly.

Local serverRuns on your machine (npx or uvx), spawned on demand. You maintain updates.
Remote serverHosted on the web with zero maintenance (e.g., Tavily search). The future default.
MCP tools consume context (each tool definition adds tokens). Disable servers you don't use. Sonnet has tool search that loads tools on demand. MCP vs skill: Use MCP to prototype fast. For production and token-sensitive work, wrap the exact API call in a reusable skill instead.

10 · Sub-agents and agent teams

A sub-agent is a mini Claude Code session with its own isolated context window, model choice, tools, and permissions. Delegate noisy or parallelizable tasks (codebase exploration, code review, test writing) to a sub-agent. It works in isolation and returns only a summary, saving your main session's context and money.

When to use sub-agents: isolated self-contained tasks, codebase exploration, code review, test generation, cheaper models for routine work
Skill vs sub-agent: Skill uses your current context; sub-agent spawns a fresh isolated session with its own window
Agent teams experimental are parallel instances that message each other and share a task list. Use git worktrees to avoid conflicts. Powerful (has built a C compiler) but expensive; disabled by default.

11 · Plugins and marketplaces

A plugin bundles skills, hooks, agents, MCP servers, and custom commands into one shareable package (with a .claude-plugin/plugin.json manifest). Install from marketplaces or version-control a shared plugin so your whole team codes with the same setup, spending, and conventions.

Best practice for teams: maintain a shared plugin and .claude directory in version control. Instant onboarding and enforced uniformity. Always vet third-party plugins because they can execute arbitrary scripts and call external APIs. Related: LSP plugins give Claude real code intelligence (go-to-definition, find references, type errors) instead of treating code as plain text.

12 · Scheduling and automation

Unlike dumb cron jobs, scheduled Claude reasons and diagnoses: it reads errors, tries alternatives, and reports findings. Three methods:

/loopRepeats a prompt or skill on a defined interval, but only while the session stays open
Headless modeclaude -p "..." runs without the UI. Pair with system cron for true server automation.
Claude routinesCloud-hosted on claude.ai. Runs on schedule, API trigger, or GitHub event with your laptop off.
Safety when automation runs unwatched
Start in read-only mode and write output to a non-destructive path
Use human gates for irreversible actions (write summary, ask for confirmation, don't auto-deploy)
Log everything. Test before scheduling. Use an environment variable to disable all schedules in emergencies.
