🌡️ Temperature & Sampling

How randomness controls creativity vs. determinism in model outputs.

🌡️ Core Concept

What Temperature Does

Before picking the next token, the model produces a raw score (logit) for every possible token in its vocabulary. Temperature divides those logits before they are passed through softmax to turn them into probabilities.
Dividing by a number less than 1 sharpens the distribution, making the already-likely token even more dominant. Dividing by a number greater than 1 flattens it, giving unlikely tokens a real shot at being picked.
Temperature does not change which token is most likely, only how confidently the model commits to that ranking versus exploring alternatives.

Low vs. High Temperature

Near 0: the distribution collapses toward always picking the single highest-probability token. Output becomes highly repetitive and predictable, the same prompt tends to produce nearly the same answer every time.
Near 1: sampling follows the model's natural learned distribution, a balance of coherence and variety that most providers use as their default.
Above 1, toward 1.5 to 2: the distribution flattens aggressively, injecting real randomness. Past a certain point this stops looking creative and starts producing incoherent, off-topic, or broken text as genuinely unlikely tokens get selected.
Temperature is a dial between "boringly safe" and "increasingly unhinged," not a dial between "bad" and "good."

Greedy Decoding vs. Sampling

Greedy decoding always takes the single highest-probability token at every step, no randomness at all. It is deterministic but tends to produce dull, repetitive text and can get stuck in loops.
Sampling draws from the (temperature-scaled) probability distribution instead of always taking the top choice, which is what makes varied, natural-sounding output possible.
Temperature near 0 approximates greedy decoding but is not mathematically identical to it in every implementation; some APIs treat temperature 0 as a special case that switches to true greedy decoding internally.
🔬 Deeper Look

Top-p (Nucleus Sampling)

Top-p restricts sampling to the smallest set of tokens whose cumulative probability reaches p (e.g. 0.9), then samples only from that shortlist, ignoring the long tail of unlikely tokens entirely.
This adapts to context: when the model is very confident, the nucleus might contain just one or two tokens; when it is uncertain, the nucleus widens to include many plausible options.
Top-p and temperature are usually applied together: temperature reshapes the whole distribution, then top-p trims off the improbable tail so wild outliers cannot get picked even at higher temperatures.

Top-k and Combining Parameters

Top-k is the simpler cousin of top-p: restrict sampling to the k highest-probability tokens (e.g. top 40) regardless of how much cumulative probability they cover, then sample among those.
Using temperature alone at high values can occasionally surface a wildly improbable token; top-p or top-k acts as a safety rail that keeps sampling within a plausible neighborhood even when temperature is turned up.

The Determinism Misconception

A common assumption is that temperature = 0 means fully deterministic, reproducible output. In practice this is not always true.
GPU floating-point non-associativity means the exact same computation can produce tiny numerical differences depending on batching and hardware scheduling, occasionally flipping which token wins a near-tie.
Mixture-of-experts (MoE) models add another source of variance: which expert a token gets routed to can depend on what else is in the current batch, so the same input can take a slightly different computational path between calls.
Temp 0 gets you close to deterministic, not a guarantee. If you need byte-for-byte reproducibility, you generally cannot rely on temperature settings alone to provide it.
🎯 Applying It

When to Use Low Temperature

Factual Q&A: you want the model's best single answer, not a randomized alternative.
Code generation: syntax has to be correct, and variety in phrasing has no value the way it does in prose.
Structured extraction and math: there is one right answer or one right schema, so consistency and predictability matter more than variety.
typical range0 to 0.3

When to Use High Temperature

Creative writing: fiction, poetry, marketing copy, where novelty and unexpected phrasing are the point, not a bug.
Brainstorming and generating varied options: asking for five different taglines benefits from real diversity between samples rather than five near-identical rewordings.
Useful when you deliberately want multiple diverse samples to pick from later, not a single best answer.
typical range0.7 to 1.2

Provider Defaults & the Hallucination Myth

Most major providers default to around 1.0 (the model's natural distribution, unscaled), letting the application override it for specific use cases rather than picking a conservative default for everyone.
Temperature does not fix hallucination. It is a randomness knob over which plausible-sounding token to pick next, not a truthfulness knob. A model can hallucinate confidently and consistently at temperature 0, and lowering temperature only makes it hallucinate the same wrong answer more reliably.
Hallucination is a knowledge and grounding problem, solved by retrieval, better prompting, or fact-checking, not by turning a randomness dial down.
⚠️ Reliability

Failure Modes

Repetition loops at very low temperature: the model can get stuck cycling the same phrase when the single highest-probability token keeps pointing back at recently generated text.
Incoherent rambling at very high temperature: past roughly 1.5 output can drift into broken grammar, off-topic tangents, or nonsense words as low-probability tokens get selected too often.
False confidence in reproducibility: teams assume temp 0 output is safe to diff or cache byte-for-byte and get surprised by drift from floating-point or MoE routing effects.
Wrong tool for the job: raising temperature to try to fix repetitive or generic-sounding answers when the real fix is a better prompt or more specific instructions.

Where It Fits

Temperature and its companion sampling parameters sit at the very last step of generation, after the model has computed its probability distribution over the next token, deciding how that distribution gets turned into an actual chosen token.
It has no effect on what the model "knows" or how it reasons; it only affects the final selection step, repeated once per output token.
Everything upstream (prompt, retrieved context, system instructions) shapes the distribution; temperature only shapes how that distribution gets sampled.

Real World Example

A code assistant defaults to temperature 0 to 0.2 so the same request produces consistent, compilable code across retries, with top-p left near its default to avoid rare syntax-breaking outliers.
A brainstorming tool generating ad copy variants uses temperature 0.8 to 1.0 with top-p around 0.95, deliberately sampling multiple times per request so the user sees genuinely different options rather than five near-duplicates.
The same underlying model, same weights, same prompt template, tuned to opposite ends of the temperature range depending purely on whether the product needs consistency or variety.
